# Local Knowledge Base Agent (Agentic RAG)

Локальный ИИ-помощник для поиска и ответов по личной базе заметок (`.md`, `.txt`). Проект построен на архитектуре **Agentic RAG** с самопроверкой релевантности документов на базе **LlamaIndex** и **LangGraph**.

## Архитектура и логика работы

Вместо классического линейного RAG, который слепо передает в LLM любые найденные тексты, здесь реализован управляемый граф состояний с фильтрацией шума:

```text
[START] ──▶ [retrieve] ──▶ [grade_documents] ──(есть релевантные)──▶ [generate] ──▶ [END]
                                   │
                           (нет релевантных)
                                   │
                                   ▼
                                 [END] (честный отказ без галлюцинаций)
```

1. **Индексация (`LlamaIndex` + `PyStemmer`):**
   - `SimpleDirectoryReader` загружает локальные заметки из директории `./notes`.
   - `SentenceSplitter` разбивает тексты на перекрывающиеся чанки (`chunk_size=512`, `overlap=50`).
   - `BM25Retriever` с русским стеммером Snowball (`PyStemmer`) строит лексический индекс с учетом морфологии русского языка.
2. **Поиск (`retrieve`):** извлекает топ-3 наиболее близких фрагмента по алгоритму BM25 и отсекает документы с нулевым скором.
3. **Оценка релевантности (`grade_documents`):** LLM выступает в роли критика и проверяет каждый найденный фрагмент на соответствие вопросу пользователя (`yes / no`).
4. **Условная маршрутизация и генерация (`generate`):** если релевантные заметки найдены, модель формирует ответ строго на их основе. Если подходящих данных нет — граф завершает работу без попытки придумать ответ.

## Почему выбран такой стек

- **BM25 + стемминг вместо векторной БД:** для локальной базы на сотни заметок тяжелые векторные хранилища и модели эмбеддингов избыточны. Лексический поиск BM25 работает за миллисекунды на CPU, не требует GPU и точно находит технические термины, названия конфигов и тексты ошибок.
- **LangGraph для оркестрации:** позволяет явно контролировать поток данных через типизированное состояние (`TypedDict`) и отсекать нерелевантный контекст до этапа генерации ответа.
- **Независимость от провайдера LLM:** проект работает через стандартный OpenAI-совместимый клиент — можно подключать как локальные модели (**Ollama**), так и облачные API (**OpenRouter**, **OpenAI**).

## Установка и запуск

1. **Клонируйте репозиторий и создайте виртуальное окружение:**
   ```bash
   python -m venv .venv
   source .venv/bin/activate  # для Linux/macOS
   # .venv\Scripts\activate   # для Windows
   ```

2. **Установите зависимости:**
   ```bash
   pip install langgraph llama-index-core llama-index-retrievers-bm25 PyStemmer openai
   ```

3. **Настройте подключение к LLM (опционально):**
   По умолчанию скрипт подключается к локальной **Ollama** (`http://localhost:11434/v1`). Для работы с другим провайдером задайте переменные окружения:
   ```bash
   export OPENAI_BASE_URL="https://openrouter.ai"
   export OPENAI_API_KEY="ваш_api_ключ"
   export OPENAI_MODEL="openai/gpt-4o-mini"
   ```

4. **Запустите ассистента:**
   ```bash
   python main.py
   ```
   *При первом запуске, если папка `./notes` пуста, скрипт автоматически создаст в ней несколько тестовых заметок для демонстрации работы.*

5.Docker
docker build -t notes-agent .
docker run -it --rm --add-host=host.docker.internal:host-gateway -e OPENAI_BASE_URL="http://docker.internal" -v $(pwd)/notes:/app/notes notes-agent
